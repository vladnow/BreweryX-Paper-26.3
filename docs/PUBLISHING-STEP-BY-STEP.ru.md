# Публикация неофициального порта BreweryX на Paper 26.3

Проверено по официальным правилам площадок 21 октября 2026 года. Это инструкция для локально подготовленной беты. Репозиторий, релиз и страницы на площадках ещё не опубликованы. Интерфейс может меняться; ниже приведены названия разделов и полей, а не обещание неизменных координат кнопок.

## Куда можно выкладывать именно эту сборку

| Площадка | Вывод |
|---|---|
| GitHub | Можно опубликовать исходники и JAR с соблюдением GPLv3. Самый прямой вариант для этого порта. |
| CurseForge / Bukkit Plugins | Можно подать документированный форк на модерацию. Нужны авторство, исходники, своё описание, изменения и правильная категория. Одобрение не гарантировано. |
| Hangar | Небольшой порт активно поддерживаемого проекта не имеет гарантированного допуска: правила требуют значимых изменений либо продолжения заброшенного проекта. Сначала согласовать допустимость с модерацией. |
| Modrinth | Для текущего порта не рекомендована публичная заявка: правила требуют существенно отличающийся форк и отдельно оценивают созданные ИИ изменения форка. Добавленные здесь изменения и материалы подготовлены ИИ. Простая отметка об ИИ не снимает ограничение. |
| SpigotMC | Текущий небольшой порт нельзя уверенно считать допустимым: запрещены чужие ресурсы и небольшие правки. Сначала получить разъяснение модерации. Сам плагин собран только для Paper 26.3. |

Лицензионное право на распространение и решение модераторов — разные вещи. Оригинал BreweryX остаётся активно поддерживаемым проектом; не называй этот порт «официальным обновлением» или «продолжением заброшенного BreweryX».

## Какие файлы использовать

- Устанавливаемый JAR: `F:\ИИшка\Готовые-JAR\Плагины\BreweryX-3.7.1-paper26.3.1-beta.1.jar`.
- Такой же проверенный оригинал сборки: `F:\ИИшка\моды\BreweryX-Paper-26.3\dist\BreweryX-3.7.1-paper26.3.1-beta.1.jar`.
- Полные исходники с файлами сборки: `F:\ИИшка\моды\BreweryX-Paper-26.3\dist\BreweryX-3.7.1-paper26.3.1-beta.1-source.zip`.
- Чистая папка для GitHub: `F:\ИИшка\моды\BreweryX-Paper-26.3\publication\github-source`.
- Описание на английском: `F:\ИИшка\моды\BreweryX-Paper-26.3\publication\description.en.md`.
- Оформленное описание для визуального редактора: `F:\ИИшка\моды\BreweryX-Paper-26.3\publication\description.en.html`.
- Изменения: `F:\ИИшка\моды\BreweryX-Paper-26.3\publication\changelog.en.md`.
- Контрольные суммы: `F:\ИИшка\моды\BreweryX-Paper-26.3\dist\checksums.sha256`.
- Отчёт проверок: `F:\ИИшка\моды\BreweryX-Paper-26.3\verification\RESULTS.ru.md`.

`-sources.jar` содержит Java-исходники и ресурсы, но для GPL и удобства пересборки распространяй также полный `-source.zip`: в нём есть сборочные файлы и лицензии. В серверную папку `plugins` кладётся только обычный runtime JAR. Оригинальный BreweryX одновременно с портом устанавливать нельзя: у них одно техническое имя плагина.

## Условия лицензии

Основа — [BreweryTeam/BreweryX, тег 3.7.1](https://github.com/BreweryTeam/BreweryX/tree/3.7.1), commit `343872c66a6f37ec4da420cbf12637b4574d5d21`. В исходниках указана GNU GPL v3 или более поздняя; карточка Modrinth указывает GPL-3.0-only. Этот выпуск распространяется на условиях GPLv3, что соответствует обоим указаниям.

1. Сохрани `LICENSE.txt`, заголовки авторства и `PORT-NOTICE.md`.
2. Сохрани упоминание BreweryTeam и оригинальных авторов Brewery. Не объявляй весь BreweryX своей разработкой.
3. При распространении JAR предоставляй точные соответствующие исходники и сборочные файлы: публичный репозиторий с нужным тегом и полный `-source.zip` рядом с JAR. Исходники чужого тега не подходят.
4. Укажи, что код изменён 21.10.2026, это неофициальный порт и бета. Не обещай проверенную работу со всеми аддонами и другими серверами.
5. Выбирай GPLv3, не MIT и не All Rights Reserved для кода этого форка. Отдельные встроенные библиотеки сохраняют собственные лицензии; их уведомления включены в JAR.
6. Не добавляй запрет на копирование/модификацию получателям и не закрывай соответствующие исходники.

Отдельное разрешение BreweryTeam для использования GPL-кода по GPL обычно не требуется. Права на логотипы, название как товарный знак и чужие материалы не следует автоматически приравнивать к правам на код. В наборе нет заимствованной рекламной графики.

## GitHub — подробный порядок

### Исходники

1. Войди в [GitHub](https://github.com/). Пароль, коды 2FA и токены вводи только на официальном сайте.
2. Установи [GitHub Desktop](https://desktop.github.com/download/), войди через **File → Options → Accounts → Sign in**.
3. Для сохранения связи с оригиналом открой [репозиторий BreweryX](https://github.com/BreweryTeam/BreweryX), нажми **Fork** справа сверху.
4. В **Owner** выбери свой аккаунт; **Repository name** — `BreweryX-Paper-26.3`. Нажми **Create fork**. Название можно изменить, если уже занято.
5. В созданном форке нажми **Code → Open with GitHub Desktop**. Выбери отдельную пустую папку, например `F:\ИИшка\Личные разработки\BreweryX-Paper-26.3-publish`, и **Clone**.
6. В Desktop выбери **Branch → New branch**, введи `paper-26.3-port`, нажми **Create branch**. Не изменяй репозиторий BreweryTeam.
7. Открой указанную выше папку `publication\github-source`. Скопируй её содержимое, включая `src`, `gradle`, `third-party-licenses`, в папку своего клона с заменой соответствующих файлов. Не копируй внешнюю папку проекта целиком.
8. В клоне удали старые сценарии автоматической публикации оригинала из `.github\workflows`, а также оригинальные `Jenkinsfile` и `.travis.yml`: они относятся к чужому выпускному процессу. Сама локальная исходная копия в рабочем проекте сохраняется.
9. В `README.md` замени пометку о будущей ссылке на адрес своего репозитория. Проверь, что сохранены ссылка на BreweryTeam, GPL и пометка о неофициальном порте.
10. В Desktop открой **Changes**. Здесь должны быть исходники и документы, а не серверные миры, базы, кэш, логи или токены. Папки `verification`, `tools`, `upstream` в загрузку не включай.
11. В **Summary** введи `Port BreweryX 3.7.1 to Paper 26.3`, нажми **Commit to paper-26.3-port**, затем **Publish branch** или **Push origin**.
12. На GitHub переключись на ветку `paper-26.3-port`. Проверь, что открываются `LICENSE.txt`, `PORT-NOTICE.md`, `build.gradle.kts` и исходники. При желании назначь эту ветку основной в настройках своего форка.

Официальная инструкция по [созданию форка](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/working-with-forks/fork-a-repo). Никому писать или отправлять pull request для выпуска своей GPL-версии не требуется.

### Релиз с готовым JAR

1. В своём репозитории открой **Releases** справа, затем **Draft a new release** / **Create a new release**.
2. В **Choose a tag → Find or create a new tag** введи `v3.7.1-paper26.3.1-beta.1`; выбери создание нового тега.
3. В **Target** обязательно выбери свою ветку `paper-26.3-port` с загруженными изменениями. Тег на оригинальном `master` выпустит неправильные исходники.
4. **Release title**: `BreweryX 3.7.1 — unofficial Paper 26.3 port — beta.1`.
5. В описание вставь `changelog.en.md`, добавь требования **Paper 26.3 / Java 25** и ссылку на исходники своего форка.
6. В область **Attach binaries by dropping them here or selecting them** перетащи из `dist` обычный JAR, полный `-source.zip`, `checksums.sha256`. `-sources.jar` можно добавить дополнительно.
7. Отметь **Set as a pre-release**. Не обозначай эту бету стабильной.
8. Сначала нажми **Save draft**, проверь файлы и тег. Затем **Publish release**.
9. Открой страницу релиза в приватном окне без входа. Скачай JAR и сравни SHA-256 с `checksums.sha256`. Полная исходная версия должна скачиваться с той же страницы.

Официальная справка: [управление релизами](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository).

## CurseForge — Bukkit Plugins

1. Войди на [CurseForge Authors](https://authors.curseforge.com/). Нажми **Create → Start a Project** либо открой [создание проекта](https://authors.curseforge.com/#/projects/create/choose-game).
2. Выбери **Minecraft**, затем класс **Bukkit Plugins**. Это серверный плагин, не **Mods**, не Fabric и не Forge.
3. **Name**: например `Brewery Continuum` — предварительно проверь доступность. **Summary**: `An unofficial BreweryX compatibility port for Paper 26.3 with custom brewing, distilling and barrel aging.`
4. Выбери подходящую категорию для игровых механик/ролевой игры из реально доступных. Не выбирай посторонние категории ради охвата.
5. Для **Logo** нарисуй собственную простую иконку 400×400 в Paint. Логотип оригинала в набор не включён. Имя и иконка не должны создавать впечатление официального BreweryX.
6. В **Description** вставь английское описание из набора. Для визуального редактора открой `description.en.html` в браузере, выдели только оформленный текст описания, **Ctrl+C**, затем обычный **Ctrl+V** в редактор. Для Markdown-режима используй `.md`.
7. **License**: GNU General Public License version 3 / GPLv3. В полях **Source**, **Issues**, **Website** укажи свои реальные публичные страницы GitHub. Не указывай выдуманный адрес.
8. На странице проекта открой **Files → Upload file**. Выбери обычный runtime JAR из `dist` или склада. В Bukkit Plugins загружается `.jar`; рекомендация `.zip` из общей справки не означает, что плагин нужно упаковывать как модпак.
9. **Display name**: `3.7.1-paper26.3.1-beta.1`; **Release type**: **Beta**; **Game version / Supported versions**: только **26.3**. Если 26.3 отсутствует, не ставь 1.21 вместо неё — дождись обновления списка или обратись в поддержку.
10. Вставь `changelog.en.md`. Базовый BreweryX не добавляй как обязательную зависимость: порт его заменяет. Сторонние интеграции объявляй только если реально требуются твоей конфигурации.
11. Нажми **Upload file / Submit**. Убедись, что появился статус **Processing** или **Under Review**.
12. Дождись **Approved** и проверь публичную загрузку без входа. При **Changes required / Rejected** исправь замечания в существующем проекте; не создавай дубликаты для обхода модерации.

Допуск зависит от модерации, включая оценку содержания проекта; BreweryX моделирует в том числе алкогольные напитки, поэтому не скрывай функциональность и не делай ложных возрастных обещаний. Публичные исходники и точный исходный ZIP предоставляй через поле Source и GitHub; сам файл плагина загружай на CurseForge.

Источники: [создание и отправка проекта](https://support.curseforge.com/support/solutions/articles/9000197241-creating-and-submitting-a-project), [правила модерации](https://support.curseforge.com/support/solutions/articles/9000197279-project-and-modpack-moderation-policies), [лицензии и форки](https://support.curseforge.com/support/solutions/articles/9000222335-submitting-a-copyright-claim-on-curseforge).

## Hangar — сначала проверить допустимость форка

Правила требуют **значимых изменений** либо продолжения действительно заброшенного проекта. BreweryX обновляется. Этот порт небольшой; оценка, что его отличий может не хватить, — вывод из правил, а не полученный отказ модератора.

1. Прочитай [Resource Guidelines → Forks of Existing Projects](https://hangar.papermc.io/guidelines/).
2. Через доступный на сайте канал поддержки уточни, допустим ли именно этот неофициальный порт. Приложи ссылку на свой GitHub, `PORT-NOTICE.md`, список изменений и укажи, что оригинал активен. Это действие выполняешь ты; сообщений от твоего имени не отправлялось.
3. Если модераторы подтвердят допустимость, войди на [Hangar](https://hangar.papermc.io/) через **Log in / Sign up**.
4. В меню аккаунта выбери **New project / Create project**. Если название кнопки поменялось, ищи раздел управления проектами.
5. **Name**: например `Brewery Continuum`, без `Paper`, `26.3` и рекламного слогана в имени. В описании явно укажи неофициальный порт BreweryX, оригинальных авторов, GPLv3 и фактические изменения.
6. Заполни ссылки **Source**, **Issues**, лицензию и подходящую категорию. Не включай платные функции или платный обязательный доступ.
7. После создания открой **Versions → New version**. Версия `3.7.1-paper26.3.1-beta.1`, канал **Beta**.
8. **Platform**: **Paper**; совместимая версия: **26.3**. Загрузи runtime JAR напрямую и добавь changelog. Не отмечай Folia, Velocity или Waterfall.
9. Перед отправкой проверь доступность соответствующих GPL-исходников. Сохрани/опубликуй версию предложенной кнопкой, дождись проверки, проверь скачивание без входа.

Если значимость изменений не подтвердят, используй GitHub; переименование и отметка «fork» сами по себе не выполняют требования Hangar.

## Modrinth — почему сейчас не стоит отправлять публично

Правила определяют форк как **существенно разошедшуюся** изменённую копию. Дополнительно [правила об ИИ](https://support.modrinth.com/en/articles/16551575-disclosure-and-usage-of-ai) оценивают новые изменения самого форка, а не просто долю человеческого кода в исходном BreweryX. Добавленная этим запуском часть создана ИИ. Поэтому нельзя обещать, что публичный выпуск этого порта будет допустим, и нельзя обходить ограничение ложной отметкой «без ИИ».

Если в дальнейшем появятся содержательные собственные человеческие изменения и будет подтверждён допустимый статус, обычный маршрут такой:

1. Войти на [Modrinth](https://modrinth.com/), открыть меню аватара → **Create a project**.
2. Выбрать **Plugin**, самостоятельное название, своё описание и лицензию **GPL-3.0-only**.
3. В **Content disclosures** указать **Contains derivative content**, ссылку на BreweryX и его авторов. Правдиво указать **Contains AI-generated content** и роль ИИ именно в порте/описании, не приписывая её оригиналу.
4. Объявить унаследованную телеметрию bStats как **Opt-out**: она включена по умолчанию и отключается в `plugins/bStats/config.yml`. При самостоятельном включении проверки обновлений сообщить и об этом соединении.
5. **Versions → Upload a version**: runtime JAR, **Beta**, **Minecraft 26.3**, **Paper**, **server required / client unsupported**, changelog, ссылки на свои соответствующие исходники.
6. Пройти **Publishing checklist** и отправку на рассмотрение только при допустимости проекта. Не использовать ИИ-иллюстрации, иконки и баннеры: площадка отдельно запрещает такие изображения.

Для текущего набора эти шаги не являются рекомендацией нажать финальную публичную отправку. Статус unlisted тоже не следует считать автоматическим разрешением на обход правил: нужно разъяснение поддержки.

Источники: [Copyright and Reuploads](https://modrinth.com/legal/rules), [ИИ и форки](https://support.modrinth.com/en/articles/16551575-disclosure-and-usage-of-ai), [Content Disclosures](https://support.modrinth.com/en/articles/16567675-content-disclosures).

## SpigotMC — условный маршрут после согласования

[Правило 4.1.2](https://www.spigotmc.org/wiki/spigot-rules/) запрещает размещать чужие ресурсы, включая небольшие изменения. Лицензия GPL сама по себе не отменяет это правило площадки. Тестов на Spigot нет: сборка использует API Paper.

После согласования допустимости с командой ресурсов: **Resources → Add Resource**, подходящая категория, своё название и краткое описание, версия `3.7.1-paper26.3.1-beta.1`, прямая загрузка JAR либо разрешённая прямая ссылка на конкретный GitHub asset. Вверху описания укажи **Requires Paper 26.3 and Java 25; not tested on Spigot**. Приложи Source Code, GPL и авторство оригинала. Затем **Save / Submit Resource** и проверка результата. Не используй Premium для обхода ограничений. Логин/2FA проходятся вручную; автоматических публикаций на этой площадке набор не делает.

## Что проверить после любой публикации

1. Публичная страница открывается без входа, скачивание возвращает JAR, а не HTML-страницу ошибки.
2. Скачанный файл совпадает с локальным по SHA-256. В PowerShell: `Get-FileHash -Algorithm SHA256 -LiteralPath 'ПОЛНЫЙ_ПУТЬ_К_СКАЧАННОМУ_JAR'`.
3. Доступны полные исходники именно опубликованного выпуска. Автоматический GitHub Source code ZIP подходит только если тег указывает на изменения порта и содержит нужные сборочные файлы.
4. Видны **Beta**, **Paper 26.3**, **Java 25**, неофициальность, авторство и GPLv3. Не добавлены непроверенные версии/платформы.
5. Статус «загружен» отличается от «прошёл модерацию» и «доступен публично». До проверки скачивания не сообщай игрокам, что релиз уже опубликован.
